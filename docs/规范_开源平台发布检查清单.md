# 开源平台发布检查清单

> 适用：GitHub / Gitee 等公开仓库，任何 push / release / 文档发布前必须过此清单。
> 创建：2026-10-05（教训来源：PAT 明文暴露、脱敏重写历史、Gitee LFS 报错、AI 品牌名版权清理、端口迁移后隧道断连）
> 说明：本文档为公开版，所有真实敏感值一律用占位符 `<PLACEHOLDER>` 表示；维护者需将占位符替换为自己的实际值后再执行扫描。

## 一、禁止上传清单

### 1. 凭据与密钥（最高优先级）
- API Token / PAT：`ghp_`（GitHub）、`glpat_`（GitLab）、Gitee 私人令牌、微信/钉钉等第三方 token
- SSH 私钥：`<SSH_KEY_DEV>`、`<SSH_KEY_VPS>`、任何 `*.pem / *.key`（含 OpenSSH PRIVATE KEY 头）
- 环境变量文件：`.env`、`*.memory_api_token`、`~/.git-credentials`、含密码的 `config.json`
- 云厂商凭据：AK/SK、`~/.aws`、`~/.kube`、`~/.ssh`

### 2. 地址与网络拓扑
- VPS 公网 IP：`<VPS_PUBLIC_IP>`、云厂商主机名（`iZ...` 段）
- 内网 / WG 地址：`<WG_SUBNET>`、`192.168.x.x`、`10.184.x.x`
- 端口与服务：SSH 默认端口/自定义端口、内部服务端口、隧道端口、调试服务端口
- 域名与内部主机名：`<INTERNAL_HOST>` 相关内部记录

### 3. 设备与调试信息
- 设备序列号：`<DEVICE_SERIAL>`
- Debug token：`<DEBUG_TOKEN>`、`FLAG_DEBUGGABLE`、`adb` 连接记录、`logcat` 脱敏前日志
- 手机内网 / 热点 IP：`<WG_PHONE_IP>`、动态热点段

### 4. 内部词汇与代号（发布文档/README/commit 前自查）
- 开发机代号、内部 agent 名、内部链路代号
- 内部邮箱：`<INTERNAL_EMAIL>`（是否愿意公开需人工确认）
- 记忆库路径：`<MEMORY_DIR>`、内部记忆服务名
- 会话/内部流程专用术语：`<INTERNAL_TERM>` 等仅内部使用的词

### 4.1 第三方品牌与版权（2026-10-05 新增：代码注释中发现 AI 助手名后清理）
- 第三方 AI 品牌名（把你要拦截的品牌词填入第二节扫描命令的 `<BRAND_NAME>`，如你环境中用到的 AI 助手名及公开大模型品牌）禁止出现在公开仓库任何位置（注释/文档/LICENSE），涉及商标与版权风险
- LICENSE 版权行只用发布者名义（如 `aixtin`），禁止写内部/第三方品牌名
- 对标/参考类注释用中性词替代品牌名：`竞品`、`参考实现`、`对标方案`

### 4.2 人称与称呼（公开内容措辞，2026-10-05 新增）
- 公开注释/文档避免用`你`/`我`/`他`/`用户`/`老板`指代对话双方或 AI 助手（内部称呼仅限内部语境）
- 产品 UI 文案的"你我"交互语气、代码注释"它/我们"指代技术对象除外
- README/SECURITY/AGENTS 等面向公众文档用中性表述，不出现内部称呼与 AI 名字
- 禁止在公开内容添加"AI 生成""仅供参考""由 AI 撰写"等标注/免责声明（2026-10-05 用户确认）

### 5. 垃圾与中间文件
- 构建产物：`build/`、`app/build/`、`*.apk`、`*.aab`、`*.onnx`（大模型视策略）
- 备份包：`*.bundle`、`*.tgz`、`*.tar.gz`、`src_ref.tgz`、`backups/`、`scripts_archive/`
- 日志与临时：`*.log`、`*_api_*.log`、`temp/`、`*.tmp`、IDE 目录 `.idea/`、`.vscode/`、`*.iml`
- 系统文件：`.DS_Store`、`Thumbs.db`、`*.swp`

## 二、发布前检查流程（5 步，全部通过才 push）

1. **git status 目检**：确认暂存清单里没有 `~`、`.key`、`.env`、`backup`、`archive`、`log` 类文件
2. **敏感模式扫描**（push 前执行，分两级；`<PLACEHOLDER>` 请替换为你的实际值）：
   - **硬敏感**（凭据/密钥/公网 IP/设备序列号/debug token/第三方品牌词）—— **0 命中**才放行：
   ```bash
   grep -rnE "(ghp_[A-Za-z0-9]{20,}|glpat_|BEGIN (RSA|OPENSSH|EC) PRIVATE KEY|<VPS_PUBLIC_IP>|<WG_SUBNET>|<DEVICE_SERIAL>|<DEBUG_TOKEN>|<BRAND_NAME>)" --exclude-dir=.git .   # <BRAND_NAME> = 以 | 分隔的品牌词列表
   ```
   - **软敏感**（内部代号与拓扑词：`<INTERNAL_HOST>`、`<MEMORY_DIR>`、`<INTERNAL_TERM>` 等）—— **人工抽查**，不入自动化：
   ```bash
   grep -rnE "(<INTERNAL_HOST>|<MEMORY_DIR>|<INTERNAL_TERM>)" --exclude-dir=.git .
   ```
   硬敏感命中任何一项 → 处理后再发；软敏感逐条人工判断语境后放行
3. **.gitignore 核对**：`build/ *.log *.bundle *.tgz *.key *.pem .env temp/ backups/ scripts_archive/`
4. **历史提交抽查**：`git log --oneline -20` 快速扫一遍近期 commit 说明；大动作前可用 gitleaks/trufflehog 全量扫
5. **大文件与平台限制核对**：>50MB 文件、LFS 依赖（Gitee 免费版不支持 LFS）→ 先确认目标平台策略

## 三、脱敏替换原则（发现敏感值后的标准做法）

| 类别 | 占位符 |
|------|--------|
| VPS 公网 IP | `<VPS_PUBLIC_IP>` |
| 设备序列号 | `<DEVICE_SERIAL>` |
| 手机内网 IP | `<WG_PHONE_IP>` |
| 开发机 / VPS 私钥 | `<SSH_KEY_DEV>` / `<SSH_KEY_VPS>` |
| Debug token | `<DEBUG_TOKEN>` |
| 内部域名 | `<INTERNAL_HOST>` |
| 开发机代号 | `<DEV_MACHINE>` |
| 内部邮箱 | `<INTERNAL_EMAIL>` |
| 内部路径 / 服务 | `<MEMORY_DIR>` / `<INTERNAL_TERM>` |

规则：把真实敏感值替换为占位符后再入库；占位符不得再被替换回真实值提交。

## 四、平台注意事项

- **GitHub**：支持 LFS（5GB 免费配额）；公开仓库历史不可逆，泄露即视为失效
- **Gitee**：免费版**不支持 LFS**（付费/试用企业版才有）；单仓库大小限制严格；镜像时 LFS 文件需普通化（`git hash-object -w` + `update-index --cacheinfo` 绕过 `filter.lfs.required=true`）
- **令牌最小化**：只给 `public_repo`/`repo` 最小权限；不同平台令牌互不通用（GitCode 令牌 ≠ Gitee 令牌）
- **个人空间地址**：Gitee 仅可修改一次，改后仓库 URL 全部变更
- **链路/端口变更后同步依赖方**：SSH 端口迁移后必须同步 autossh 隧道、内部连接文档、防火墙、fail2ban、文档示例，否则依赖方静默失效（2026-10-05 隧道断连根因）

## 五、违规补救 SOP

1. **立即吊销泄露令牌**（GitHub/Gitee 设置页），换新令牌 —— **第一步永远是吊销，不是清理**
2. **评估影响面**：私钥泄露 → 换密钥；仅文档泄露 → 直接改文件 push；**Release 资产 / issues / commit message 中的泄露 filter-repo 清不掉**，只能删改对应条目，且公开仓库历史不可逆、泄露即视为永久失效
3. **历史已泄露（git 分支内）**：`git filter-repo` 重写历史 + force push（重写前必须 `git bundle` 备份；重写后所有本地 clone 需重新拉取，fork/PR 受影响）
4. **平台侧**：VPS 已暴露过 → 改 SSH 端口 + fail2ban；云控制台安全组同步收紧
5. **记录沉淀**：把新踩坑追加到本清单，避免复发
